name: draft-cover-letter
description: Draft the specific half of an Application's cover letter into cover-letter.json, after the applicant picks and confirms sentence by sentence which requirements of the Posting it answers. Use when the applicant asks for the letter; `jobapply run` starts it as the interactive Operator.
---

Draft the job-specific half of the cover letter for the Application named in the request (`$ARGUMENTS` in Claude Code). File formats: [docs/data-files.md](../../../docs/data-files.md); the Swiss sources behind every rule here: [docs/research/swiss-cover-letter-body.md](../../../docs/research/swiss-cover-letter-body.md) §5.

The letter follows **YOU – ME – WE**: the hook (why this role at this employer), the evidence (which requirements of the Posting the applicant answers, and where they proved it), the outlook (what they want to contribute). It says what the CV cannot: the CV already holds the address, languages, degrees, the Bachelor's and its thesis; the fixed `about_me` already states the current studies and job. The letter never spends a sentence on any of them.

1. Locate the Application folder. If `application.json` has `"cover_letter": false`, the Application waives the letter: tell the applicant and stop. Read `application.json`, `posting.json`, `snapshot.md`, the Workspace's Profile files (`profile/*.json`), and `cover-letter-fixed.json` (the fixed half, take the Application's language from each map: know what `about_me` and `closing` already say so you write around them, not over them).
2. **Show the posting facts first.** `posting.json` was filled unattended and nobody has reviewed it: print company, role, reference, workload, the contact person and the postal address as a short block, marking what is empty. This is the applicant's chance to correct `posting.json` (`jobapply open <slug> posting`) before a wrong name lands on the letter. Then continue in the same message with the next step.
3. **Offer, then stop.** One numbered list, nothing else in that message:
   - **Hook** (YOU): one or two candidate hooks, each one sentence naming the role and one concrete thing in the Posting that speaks to the applicant: a task from `posting.description` or `snapshot.md`, a product, a project, a team, a touchpoint. Where the Posting offers nothing concrete, one question: what drew them to it. Ask for one.
   - **Evidence** (ME): every line of `posting.requirements` (plus anything the Posting explicitly asks the letter to address: a choice between entry models, an own project), each with the requirement in the Posting's own words and one of:
     - a **candidate sentence**: the one sentence the letter would say, carrying the Posting's keyword and a *where/how* from a named line of a Profile file: an `experience.json` bullet, a course or the current studies in `education.json`, a named project or tool; with the number or result when the line has one.
     - a **question**, when no Profile line supplies a where/how: one line asking what the applicant would say, or whether to leave it out. A skill that `skills.json` merely lists, or a soft skill the Posting names without an `experience.json` bullet that shows it in a situation, is a question, not a sentence.
     Ask the applicant to pick **two to four**; must-haves and an explicitly required soft skill first.
   - **Pensum / start**, only when the Posting's workload range is wider than the Pensum the Profile `summary` names, or the Posting asks for a start date: one candidate sentence stating the applicant's Pensum and start.
4. **Confirm one at a time.** For each picked item, in the applicant's order, show only the sentence as it will stand in the letter (for a question, written from their answer) and wait: they approve, edit, or drop it. Move on only after the answer. After the last one, offer the **outlook** sentence (WE): one sentence on what the applicant wants to contribute or take on in this role at this employer, written from the confirmed hook and evidence; confirm it the same way. Every confirmed sentence is the applicant's own claim for this letter; a dropped item stays out.
5. Write plain prose: paragraphs of running text, the way a letter is typed, with the applicant's answers folded into sentences. Markdown stays out of the letter (no lists, no bold). Write in the Application's language, addressing the reader formally (Sie/"Dear") whatever tone the Posting uses; German uses Swiss spelling (`ss`, never `ß`). Indicative mood throughout ("Ich freue mich", "I look forward"), first person with varied sentence starts, competence stated neutrally through the evidence itself; the Posting's keyword sits inside the applicant's sentence. Use only the sentences confirmed in step 4; invent nothing. Swiss recruiters discard letters that open with «Hiermit bewerbe ich mich», «Mit (grossem) Interesse habe ich … gelesen», «auf der Suche nach einer neuen Herausforderung», "I am hereby applying", "I read with great interest", or that mirror the ad as «Sie suchen X. Ich bringe X mit.»: the confirmed hook and evidence take their place.
6. Produce, in `cover-letter.json`:
   - `subject`: empty; the tool builds "Bewerbung als <role>, Referenz <reference>" from `posting.json`. Set it only when the Posting asks for a specific wording.
   - `salutation`: empty; the tool builds it from `posting.contact` or falls back to the generic form. If `posting.contact` has no name, say so to the applicant: Swiss guides want a named reader, and the applicant may know one.
   - `intro`: a JSON list holding the confirmed hook, one or two sentences. The tool renders it and the first fixed `about_me` paragraph as one paragraph, so the hook must read naturally straight into `about_me`; no requirement goes here.
   - `body`: a JSON list of one or two paragraphs (one string each) holding the confirmed evidence sentences in turn.
   - `outlook`: a JSON list holding the confirmed outlook sentence, plus the Pensum/start sentence when one was confirmed. The tool renders it and the first fixed `closing` paragraph as one paragraph, so it must read naturally straight into the closing.
   - Leave `draft: true`. The applicant edits, then marks it done (`[d]` in `jobapply run`).
7. Show the draft to the applicant in the reply as well, then open the file for them: `jobapply open <slug> letter`.

Done when `cover-letter.json` holds intro, body and outlook, every claim in them is a sentence confirmed in step 4, every claim traces to a line in a Profile file, `posting.json` or the applicant's answer, no sentence restates the CV or `about_me`, and the total letter (fixed + specific) stays under one page (about 250 words of specific text). Minimal throughout: one sentence per requirement, one message per confirmation, no summaries between steps.
